# Bosun 0.4.5

Исправлен предел CPU, который мог превращаться в фиксированную частоту. В 0.4.4 при исходном минимуме выше выбранного потолка Bosun выставлял `min=max`: например, оба значения становились 1500 MHz.

Теперь потолок остаётся верхней границей. Более низкий исходный минимум сохраняется; если он равен потолку или выше, нижняя граница берётся из `cpuinfo_min_freq` текущего драйвера. Значение 400 MHz не зашито. Исходные min/max сохраняются для точного отката. Старый зажатый диапазон исправляется при следующем применении назначения, без удаления профилей и журнала.

Governor выбором потолка не меняется. `performance` может запрашивать верхнюю частоту даже при правильном диапазоне. Для изменения частоты по нагрузке выберите доступный `schedutil`/`ondemand` либо, на активном `amd-pstate-epp`, `powersave` с EPP. Generic `powersave` у ACPI означает запрос нижней частоты; это разные режимы. Пояснение добавлено в Desktop/Decky, а проверка CPU отдельно показывает `min=max`, `performance` и доступную динамическую политику. Если потолок равен самой низкой поддерживаемой ступени, более широкого диапазона драйвер не предоставляет.

175 Python-тестов, 39 frontend-тестов, TypeScript, сборка плагина и Qt-проверка. Четыре регрессии воспроизведены на 0.4.4. Аппаратная проверка фактической динамики частот на Steam Deck ещё требуется; показания sysfs не доказывают физическую частоту.

Обновление: **Decky → Bosun → Обслуживание и откат → Обновить Bosun и плагин**, Desktop → Обслуживание → Обновить либо `python3 /home/.bosun/app/install.py --update`. После обновления откройте плагин заново: сохранённое назначение активной игры будет применено автоматически, если автоматика включена. Для глобального CPU-профиля повторите применение. Перезагрузка SteamOS не нужна.
