# Bosun 0.4.4

Сохранённые профили игр автоматически применяются при каждом запуске и имеют приоритет над глобальными для указанных в них runtime-параметров. Сброс CPU/EPP/TDP и других выбранных значений со стороны Steam больше не считается причиной отказать игре в её профиле. Фактические внешние значения сохраняются в журнале для отката; остальные параметры и файлы сохраняют обычную проверку конфликтов.

- После старта выполняется один дополнительный проход, чтобы учесть сброс питания Steam. Нет постоянного опроса. Смена игры отменяет устаревшие события, а запоздавший exit старой игры не выключает новую.
- CLI/legacy-сессия больше не блокирует назначенную игру; позднее завершение старого launcher не откатывает новый профиль.
- После перезагрузки и обновления SteamOS/ядра профиль игры проверяется по текущим интерфейсам и применяется без ручного применения глобального профиля.
- Старый конфликт прерванной CPU-транзакции перед игровым CPU-профилем разрешается автоматически с архивированием журнала. Несвязанные конфликты не удаляются.
- При выходе восстанавливается глобальный профиль; если глобального значения нет — последнее сохранённое внешнее значение. Preview использует те же правила приоритета, не меняя систему или журнал.

Проверены повторные старты, сбросы Steam, resume, смена игр, reboot/update, legacy-токены и preview в изолированных проверках. Аппаратная проверка с реальным Steam-клиентом ещё требуется; прирост производительности не заявляется.

Обновление: **Decky → Bosun → Обслуживание и откат → Обновить Bosun и плагин**, Desktop → Обслуживание → Обновить, либо `python3 /home/.bosun/app/install.py --update`. После обновления откройте Bosun заново и убедитесь, что в заголовке 0.4.4. Сохранённые назначения остаются; включите автоматические профили, если ранее отключали их. Перезагрузка SteamOS для этого исправления не нужна.
