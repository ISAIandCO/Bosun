# Bosun 0.3.5

Исправлены две подтверждённые ошибки управления CPU. Повторное сохранение/синхронизация активного назначения теперь проверяет и применяет значения заново: прежняя версия отвечала «профиль уже активен», даже если настройка изначально была пропущена или её изменил другой инструмент. Внешнее изменение теперь видно как конфликт, а не успешное применение.

Если текущая нижняя граница CPU выше выбранного потолка, Bosun больше не пропускает настройку целиком. Он проверяет аппаратный диапазон, временно снижает нижнюю границу только при необходимости, затем меняет верхнюю. При повышении/откате диапазон сначала расширяется, чтобы соблюсти min ≤ max. Сохраняются оба исходных значения; внешнее изменение любого управляемого края блокирует перезапись всей пары. После перезагрузки учитывается новый baseline. Причины пропуска имеют явный префикс SKIP.

В блоке фактического состояния всегда показаны CPUFreq min/max, драйвер/governor и доступное показание текущей частоты, даже если Bosun не владеет настройкой. Кнопка «Проверить CPU: лимиты и частоты (2 с)» показывает активное назначение, конфликты менеджеров питания, Boost/EPP, границы, максимум наблюдений и источник показаний. Она обнаруживает сброс потолка во время наблюдения и превышение прочитанного потолка. Проверка только читает данные, не создаёт нагрузку, не устанавливает пакеты и не запускает постоянный мониторинг.

Важно: запись CPUFreq policy не объявляется доказанным аппаратным ограничением SMU/Boost. Для превышения частоты в игровом оверлее конкретная причина без данных устройства пока не установлена. Вариант PowerTools через Van Gogh SMU изучен: он требует общего AMDGPU manual mode и затрагивает общий интерфейс CPU/GPU; этот релиз не включает такой переход автоматически. Для выбора следующего исправления нужен результат новой проверки под нагрузкой игры.

Проверено: 125 Python-тестов, 28 frontend-тестов, TypeScript и поставляемая сборка. Одиннадцать новых Python-регрессий охватывают границы восьми CPU policies в LCD/OLED fixtures, повышение/понижение, откат, частичный сбой, journal recovery, внешний конфликт, reboot baseline, повтор после SKIP и наблюдение частот без записи. Пять из первых шести проверок воспроизводили ошибки 0.3.4. Физического Steam Deck нет; аппаратное соблюдение частоты этим релизом не подтверждено.

Обновление: Desktop Bosun → «Обновить Bosun», Decky → «Обновить Bosun и плагин» либо свежий `Bosun-installer.desktop`. После перезапуска Decky проверьте 0.3.5 в заголовке, заново сохраните/примените CPU-профиль и выполните проверку в запущенной игре. Сохранённые назначения и исходные значения для отката сохраняются.
