# Bosun 0.4.3

Исправлена немедленная проверка записи CPUFreq. Ядро обновляет границы policy через очередь работ, поэтому write может завершиться раньше, чем меняется readback. Bosun теперь ждёт точного значения до 500 ms после каждой записи; неизвестные значения не принимаются за успех. При дискретных частотах заранее выбирается доступный потолок не выше запроса и сообщается итоговая ступень.

Для ошибки «Interrupted transaction recovery conflicts» по scaling_min/max_freq добавлена кнопка **«Разблокировать CPU, оставив текущие лимиты»** вверху Decky и в Desktop → Обзор. Эквивалент: `bosun recover-cpu`. Она архивирует полный журнал, оставляет текущие CPU-границы без записи и снимает только их владение. Остальные изменения прерванной операции восстанавливаются с прежними проверками конфликтов. Исходные CPU-значения остаются в архиве; после этого явного выбора новые применения получают текущие CPU-границы как baseline. Назначения игр сохраняются.

В диагностике показаны before/intended/actual, доступные частоты и related_cpus. Это позволяет отличить неприменённый профиль, округление драйвером и аппаратное превышение уже записанного policy cap.

Проверено: 159 Python-тестов, 34 frontend-теста, TypeScript/build и настоящие Qt-виджеты на изолированном backend. Отложенные записи проверены на восьми policies для LCD/OLED; два сценария воспроизводят дефекты на исходниках 0.4.2. Физического Steam Deck нет: аппаратное соблюдение CPU cap и влияние на FPS/расход не заявляются.

Обновление: `python3 /home/.bosun/app/install.py --update`, затем заново открыть Bosun/Decky. При показанной ошибке recovery нажать кнопку разблокировки и повторно сохранить/применить выбранный CPU-профиль. Удалять журнал или сбрасывать всю систему не требуется.
