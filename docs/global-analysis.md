# Отбор методов во всём стеке Steam Deck

Проверка документации и исходников: 18–19 октября 2026. Область поиска: Linux CPU scheduler/VM/block/PM, SteamOS и железо Valve, AMDGPU/RADV, Gamescope, Proton/Wine, DXVK/VKD3D, sched-ext/scx, PowerTools/SimpleDeckyTDP, GameMode, CachyOS settings, CryoUtilities и SDWEAK. Исследование пользователя использовано как отправная точка, не как список обязательных значений или ограничений версии.

**Это решение по реализации, а не таблица измеренного ускорения.** Ни один метод не получил здесь процента FPS/Wh без физического A/B. «Опционально» означает работающую функцию, которую можно применить сейчас; «не включено» — конкретную техническую причину ниже. Исчерпывающего списка всех будущих оптимизаций не существует. Для этой версии завершён отбор перечисленных направлений и реализация выбранных интерфейсов.

## Глобальные, временные системные и процессные настройки

| Где действует | Как применяется | Когда возвращается |
|---|---|---|
| Постоянный глобальный профиль | CLI/Decky → валидированный Python engine → sysctl/sysfs, remount /home или собственные drop-in/GRUB | Переключение профиля, disable или rollback возвращают записанный baseline, если нет внешнего конфликта |
| Глобальные boot/login настройки | Отдельный GRUB override, zram-generator или memlock drop-ins; без замены vendor-файлов | Удаление/восстановление собственного файла, регенерация текущего GRUB; reboot/login для фактического возврата |
| Профиль игры | Decky получает события Steam → backend overlay текущего системного профиля. CLI-альтернатива: `bosun run PROFILE -- %command%` через systemd path broker | Выход/смена игры или выгрузка Decky возвращают предыдущий профиль. Это **системные** значения, они действуют на все процессы, пока идёт игра |
| Launch options конкретной игры | Decky читает `RegisterForAppDetails`, сохраняет original/last по SteamID+AppID **до** записи, вызывает `SetAppLaunchOptions`/`SetShortcutLaunchOptions`, повторно читает результат | Steam применяет строку при следующем запуске обычным пользователем. Она сохраняется до отдельного восстановления. Полный откат Decky восстанавливает её первым |

Постоянного Bosun polling/monitoring-процесса нет. LAVD работает только при явном выборе scheduler; Decky использует уже существующий PluginLoader. Suspend вызывает один reconcile/event replay; неизвестные внешние значения не перезаписываются. После изменения fingerprint SteamOS/kernel/Mesa/Gamescope автоматический системный replay приостанавливается до явной проверки/применения.

## Что отобрано и почему

| Направление и первичный источник | Реализация в 0.3 | Предполагаемая польза и граница применимости |
|---|---|---|
| [AMD P-state / CPPC / EPP](https://docs.kernel.org/admin-guide/pm/amd-pstate.html) | Boot active/passive/guided при CPPC или уже работающем AMD pstate; отдельные governor/EPP/Boost/CPU ceiling | Подбор CPU↔GPU бюджета при общем лимите APU; низкий EPP/Boost off могут ухудшить CPU frametime. На legacy driver EPP-профиль не подставляет powersave вслепую |
| [sched_ext](https://docs.kernel.org/scheduler/sched-ext.html), [LAVD](https://github.com/sched-ext/scx/tree/main/scheds/rust/scx_lavd) | Четыре реальных режима бинарника, native dependency install, BTF/interface/attach/conflict checks; service restart при смене режима | Scheduler latency и консолидация работы — кандидат для FPS/W. Не default: версии/игры различаются, есть [upstream regressions](https://github.com/sched-ext/scx/issues/3750) |
| SMT и [GameMode](https://github.com/FeralInteractive/gamemode) | Глобальный SMT on/off; дополнительно процессная affinity по фактической топологии — один online поток на ядро, без отключения SMT системы | Отдельные эмуляторы/мало-поточные игры; может сильно снизить throughput. Номер логического CPU не зашит под LCD/OLED |
| [GPU PM interfaces](https://docs.kernel.org/gpu/amdgpu/thermal.html), [SimpleDeckyTDP](https://github.com/aarron-lee/SimpleDeckyTDP/blob/main/py_modules/gpu_utils.py) | Драйверные APU power caps 4–15 W с дополнительными hardware bounds, GPU auto/low/high | Кривая эффективности по игре. Fixed MHz через скрытый OD range не реализован: `pp_od_clk_voltage` на Deck может быть пустым и не позволяет сохранить старые limits. Для фиксированных MHz доступен штатный Steam UI |
| [GPU scheduler source](https://github.com/torvalds/linux/blob/master/drivers/gpu/drm/scheduler/sched_main.c) | Boot `gpu_sched.sched_policy=0/1`, только при exported parameter | RR/FIFO выбирает очередь GPU jobs, **не CPU scheduler**. Возможны отличия latency/fairness, не гарантированный FPS |
| [AMDGPU migration](https://github.com/torvalds/linux/blob/master/drivers/gpu/drm/amd/amdgpu/amdgpu_cs.c) | Boot moverate отдельно | Меняет бюджет BO migration при memory pressure, не физическую пропускную способность LPDDR5. LBPW не применяется: [реализация GFX9](https://github.com/torvalds/linux/blob/master/drivers/gpu/drm/amd/amdgpu/gfx_v9_0.c) не относится к RDNA2 Deck |
| [Per-core EPP boost, RFC разработчика](https://lists.openwall.net/linux-kernel/2026/07/28/668) | Опциональный boot `amd_pstate.epp_boost`, **только если текущий kernel сам экспортирует параметр** | Исследован RFC David Vernet июля 2026; не считается штатной функцией любой SteamOS. Ядро ради флага не патчится. Проверка интерфейса важнее номера версии |
| [MGLRU](https://docs.kernel.org/admin-guide/mm/multigen_lru.html) | Recommended включает три документированных компонента (`current \| 7`), сохраняя старшие биты; main-only/off отдельно | Более эффективный reclaim под давлением RAM. `min_ttl_ms>0` не включён: документация прямо допускает OOM kill при невозможности сохранить working set |
| [THP](https://docs.kernel.org/admin-guide/mm/transhuge.html), [VM sysctl](https://docs.kernel.org/admin-guide/sysctl/vm.html) | Defrag отдельно; THP/shmem, khugepaged, proactive/locked compaction, fragmentation/watermark/reserve/page lock/cache pressure/writeback — отдельные bounded controls | Меньше fault/compaction/I/O stalls либо больше памяти под полезные данные. THP always/высокие reserves/большие dirty caches могут дать обратный результат; поэтому presets для A/B, не все значения recommended |
| [zram-generator](https://github.com/systemd/zram-generator/blob/main/man/zram-generator.conf.md), [zswap](https://docs.kernel.org/admin-guide/mm/zswap.html), [CachyOS settings](https://github.com/CachyOS/CachyOS-Settings) | Zram page-cluster0; compressor/size через reboot-only override; queue knobs; zswap off только если **все** active swap — zram | Убрать лишний swap readahead и второй compression cache; баланс lz4/zstd по нагрузке. Без live swapoff/OOM, disk fallback не удаляется. Отключение zswap не заявляется немедленной очисткой уже существующего pool |
| [KSM](https://docs.kernel.org/admin-guide/mm/ksm.html), watchdog/perf overhead | KSM stop/start, NMI/soft/hung-task detectors, perf CPU-time budget, VM stat interval отдельно | Убрать реальные сканирования/пробуждения, если они активны. KSM stop сохраняет существующие merged pages. Выключение диагностики не меняет термозащиты; idle perf без sampling не создаёт обещанного ускорения |
| [Block queue](https://docs.kernel.org/block/queue-sysfs.html), [BFQ](https://docs.kernel.org/block/bfq-iosched.html), [Kyber source](https://github.com/torvalds/linux/blob/master/block/kyber-iosched.c) | NVMe/настоящая SD: scheduler, readahead, WBT, rq affinity, entropy, stats, depth; дополнительные Kyber/BFQ tunables. Zram queue отдельно | Streaming/loading/tail latency и overhead. `mmcblk` eMMC LCD исключается из SD. Сначала выбирается scheduler, затем его tunables: скрытые старые значения не угадываются |
| [mount, util-linux](https://github.com/util-linux/util-linux/blob/master/sys-utils/mount.8.adoc) | Recommended: remount отдельного ext4/btrfs /home noatime, сохраняет другие текущие flags и identity source/fstype | Убрать metadata writes при чтении. Если уже noatime — no-op; relatime и так уменьшает записи. Не редактирует всю fstab, смена mount/device даёт конфликт |
| [Workqueue](https://github.com/torvalds/linux/blob/master/kernel/workqueue.c) | Опциональный boot power_efficient | Консолидация WQ_POWER_EFFICIENT, меньше wakeups; цена — migration/cache/latency. Не все очереди используют этот флаг |
| [Software mitigations](https://docs.kernel.org/admin-guide/kernel-parameters.html) | Recommended `mitigations=off`; осознанное разрешённое снижение ИБ | Возможен выигрыш CPU/syscall-heavy; в GPU-bound может отсутствовать. Никакого запрета только по ИБ, повторного согласования нет |
| [USB HID source](https://github.com/torvalds/linux/blob/master/drivers/hid/usbhid/hid-core.c) | Опциональный boot poll 1–16 ms | Input latency↔wakeups для подходящего USB HID; не гарантирует polling встроенного контроллера и не ускоряет rendering |
| [systemd resource limits](https://www.freedesktop.org/software/systemd/man/latest/systemd.exec.html#LimitMEMLOCK=) | Memlock ceiling для desktop user и user manager через собственные drop-ins, reboot/login | Убирает отказ при реальном достижении locked-memory limit. Не резервирует RAM и не ускоряет игру, которая limit не достигает |
| [Mesa environment](https://docs.mesa3d.org/envvars.html) | Per-game cache size, wave32 compute/pixel/geometry, NIR cache; flags проверяются по установленным 64/32-bit RADV | Cache capacity может уменьшить повторные компиляции, wave32 — изменить occupancy. NIR cache экспериментален. Fossilize single-file cache может не учитывать этот Mesa size; не меняется весь shader cache Steam |
| [Proton 11 README](https://github.com/ValveSoftware/Proton/blob/proton_11.0/README.md), [Valve Wine sync source](https://github.com/ValveSoftware/wine/blob/bleeding-edge/server/inproc_sync.c) | Per-game sync auto очищает inherited NO_NTSYNC/NO_FSYNC/NO_ESYNC; fsync обходит NTSYNC, оставляя Fsync доступным при поддержке | Устранение старого запрета современных sync paths, A/B fallback при регрессии. Зависит от Proton/kernel; esync в Proton11 обозначен obsolete, его не навязываем |
| [DXVK config](https://github.com/doitsujin/dxvk/blob/master/dxvk.conf) | Per-game dxgi/d3d9 maxFrameLatency 1–4 | Меньше кадров в очереди/input latency; может ухудшить throughput. Это не FPS cap и не обещание производительности |
| [VKD3D-Proton](https://github.com/HansKristian-Work/vkd3d-proton) | Произвольная строка остаётся в native Steam editor; нет default feature/debug masks | Feature masks/debug workarounds специфичны для конкретного дефекта; отключение correctness/смена DX12 feature set не является общей оптимизацией Deck |
| [Gamescope](https://github.com/ValveSoftware/gamescope), [WSI issue #1712](https://github.com/ValveSoftware/gamescope/issues/1712) | Не подменяем графический стек пакетами SDWEAK. Cap/refresh/clock оставлены штатному Steam | Отключение WSI — workaround конкретного дефекта, с ограничениями HDR, особенно OLED; нельзя выдавать потерю качества за системное улучшение. Нет обоснованной единой замены Mesa/Gamescope для текущих веток обоих Deck |
| [CryoUtilities](https://github.com/CryoByte33/steam-deck-utilities), ядра CachyOS/Zen/custom | Применимые VM/THP/swap методы реализованы отдельно, без BIOS UMA/ядра/принудительного disk swap | Современный zram и shared16GB требуют нового отбора. Дополнительный swapfile/UMA reservation сами не добавляют RAM. Нет подтверждённой причины менять весь kernel+graphics stack поверх SteamOS ради уже доступных интерфейсов |

## Что именно из SDWEAK не перенесено

Сопоставление с [SDWEAK install.sh](https://github.com/Taskerer/SDWEAK/blob/main/install.sh) и [assets/SDWEAK.sh](https://github.com/Taskerer/SDWEAK/blob/main/assets/SDWEAK.sh), checked HEAD `8c32e86`. Значения не скопированы единым пакетом.

| SDWEAK | Решение Bosun |
|---|---|
| mitigations, NMI, MGLRU7, THP defrag, /home noatime, zram page-cluster | Реализованы в recommended с условиями и exact-state rollback |
| soft watchdog/hung-task, perf CPU budget, autogroup, VM compaction/reserves/watermarks/page locks/stats/cache/dirty bytes и timers, KSM, THP/shmem/khugepaged | Реализованы отдельными ключами. Не все recommended: некоторые параметры меняют latency↔throughput, некоторые совпадают с текущими defaults |
| NVMe Kyber + latency targets, SD BFQ + tunables, readahead/depth/affinity/WBT/random/stats, zram queues | Реализованы раздельно; BFQ `slice_idle_us` управляет тем же idling, дублирующая запись `slice_idle` не нужна. SD на eMMC не переносится |
| zram 200% RAM + lz4 | Доступны отдельно, через собственный generator drop-in и reboot. Нет немедленного restart занятого swap и замены `/usr/lib` config |
| gpu_sched RR, moverate256 | Реализованы boot-only опционально, обнаружение параметра обязательно |
| `amdgpu.lbpw=0` | Не применяется: GFX9-only код не охватывает RDNA2 Deck |
| `lru_gen/min_ttl_ms=200` | Не включён: защита working set может вызвать OOM kill; недостаточно универсального безопасного значения при shared RAM GPU/CPU |
| `kernel.watchdog=0` | Отдельный дублирующий ключ не нужен: выбранные NMI и soft watchdog уже управляются раздельно |
| `perf_event_max_* = 1`, printk/devkmsg off, exception-trace0, seccomp actions_logged empty | Не перенесены: главным образом урезают profiling/diagnostics; без активного sampling/log storm нет постоянного игрового ускорения. Реальный perf CPU budget и scanning controls уже доступны. Снижение ИБ не является причиной исключения |
| `aio-max-nr=1048576`, TCP buffers 16MiB | Не перенесены: повышение не достигнутого resource ceiling не ускоряет offline game; сетевой эффект зависит от transport/сервера, фиксированные buffers расходуют RAM и могут увеличить queueing |
| GameMode removal `pacman -Rdd`, TrustAll/keyring reset/cache deletion | Не требуется для выбранных методов. Удаление dependencies и конфигурации пакетной системы не улучшает FPS/W; сохраняется совместимость установленных программ |
| Старая Gamescope3.16.23.2/custom RADV и фиксированные пакеты SteamOS3.8 | Не устанавливаются: в проверенном дереве нет достаточной patch source/совместимости для всей текущей SteamOS; установка произвольной старой версии может сделать downgrade. WSI workaround нельзя смешивать с HDR-регрессией |
| LCD70Hz | Не применяется: разгон панели с индивидуальной стабильностью, иное потребление; не универсальная системная оптимизация и неприменим к OLED90Hz |
| `amd_pstate=active` + energy.path, постоянно возвращающий EPP power | Boot mode и EPP реализованы; повторная перезапись чужой power policy не переносится. Bosun выполняет один event apply/resume и сообщает конфликт |

## Остальные проверенные границы

* Undervolt/overclock/BIOS UMA, APST/PCIe ASPM и Wi-Fi power-save не имеют универсального значения без риска нестабильности, задержек устройства/сети или корректного firmware rollback. Нельзя гарантировать стабильность конкретного APU по модели DMI. Bosun не меняет аппаратные защиты температуры/тока.
* Не включаем `RADV_PERFTEST=gpl` как «новое ускорение» там, где GPL уже штатен, `DXVK_ASYNC=1` для upstream DXVK, старые esync-рецепты и split-lock-настройки Intel для AMD Zen2.
* Автоматическое удаление shader caches, compatdata, swapfile, перемещение данных и drop_caches не улучшает устойчивую производительность; может вызвать recompilation/loading или потерю пользовательских файлов.
* SMT/CPU cap/TDP/EPP/wave size/storage scheduler не получают одного оптимального значения для всех игр. Готовые профили — проверяемые кандидаты; приёмка требует FPS/lows/frametime **и** battery Wh при одинаковом качестве, cap и сцене.
