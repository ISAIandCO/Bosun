# Bosun

**One tool to tweak them all**

Bosun — устанавливаемый инструмент системных настроек для Steam Deck LCD и OLED под SteamOS. Он применяет твики, сохраняет исходные значения и возвращает их при откате. Цель — лучшая игровая производительность на ватт: более ровный кадр при том же расходе или меньший расход при сохранении выбранного FPS и графики.

**Версия 0.1.0. Физические LCD/OLED пока не протестированы. Процентов прироста и увеличения автономности не обещаем.** Механизмы проверены по документации и исходникам, установка и транзакции — изолированными тестами. Для игры, которая помещается в RAM и упирается в GPU, часть системных твиков может не дать эффекта. После установки рекомендуется сравнение до/после.

## Установка

В Desktop Mode скачайте [Bosun-installer.desktop](https://raw.githubusercontent.com/ISAIandCO/Bosun/main/Bosun-installer.desktop), поместите на рабочий стол и запустите. В Dolphin разрешите выполнение файла, если KDE запросит доверие. Откроется терминал; установщик запросит пароль пользователя Steam Deck. Если пароль ещё не задан, задайте его командой `passwd` в Konsole.

Альтернатива в Konsole:

```bash
curl --fail --location --proto '=https' --proto-redir '=https' \
  https://raw.githubusercontent.com/ISAIandCO/Bosun/main/install.py -o /tmp/bosun-install.py
python3 /tmp/bosun-install.py
```

Нужны штатные Python 3.10+, sudo, systemd, curl для desktop-установщика. Python-зависимостей, Decky и пакетов из pacman устанавливать не нужно. При загрузке установщик определяет commit `main` и получает именно его файлы, а не смесь разных обновлений.

Появятся **Bosun** на рабочем столе и в меню приложений. Можно запускать `~/.local/bin/bosun`; в примерах ниже он сокращён до `bosun` (при необходимости используйте полный путь).

Установка сама не применяет профиль. Откройте Bosun → **Предпросмотр рекомендуемого профиля** → **Применить рекомендуемый профиль**. Если изменились загрузочные параметры, перезагрузитесь. В меню есть фактическое состояние, выбор и создание профилей, отключение отдельных твиков, обновление и полный откат.

## Что меняет рекомендуемый профиль

| Настройка | Фактическое действие | Зачем и ограничения |
|---|---|---|
| Программные CPU mitigations | `mitigations=off` в отдельном override GRUB | Уменьшение overhead защит от CPU-уязвимостей. Компромисс с ИБ осознанный. Выигрыш зависит от игры; требуется перезагрузка. |
| NMI watchdog | `kernel.nmi_watchdog=0` | Убирает работу hard-lockup detector через perf/NMI. Возможен небольшой эффект; диагностика жёстких зависаний станет слабее. Термозащиты не затрагиваются. |
| Swap readahead | `vm.page-cluster=0` при активном zram на наивысшем приоритете | Не распаковывать соседние swap-страницы заранее. Может снизить задержку первого fault, но увеличить число последующих faults. Низкоприоритетный disk swap сохраняется. |
| MGLRU | Включает только главный бит `lru_gen/enabled`, сохраняя остальные | Reclaim по поколениям при нехватке памяти. Если уже включён, это честно показанный no-op. |
| Дефрагментация THP | `defrag=defer+madvise` | Фоновая компактация для обычных областей, direct compaction остаётся для `MADV_HUGEPAGE`. В сравнении с `always` уменьшает риск stalls, в сравнении с `madvise` может добавить фоновую работу. Нужен A/B; THP allocation policy не меняется. |

Это рабочий стартовый профиль, **не доказанный универсальный максимум**. У некоторых актуальных SteamOS большинство runtime-значений уже совпадёт. Bosun не записывает их ради видимости и не объявляет совпадение приростом. Отсутствующие интерфейсы пропускаются отдельно с причиной. Отключить конкретную настройку можно через меню или `bosun disable ИМЯ`.

## Профили и игры

```bash
bosun status
bosun apply recommended --dry-run
bosun apply recommended
bosun disable thp_defrag
bosun rollback --dry-run
```

При глобальном переключении старые настройки, которых нет в новом профиле, откатываются. Поэтому `bosun apply battery` заменяет рекомендуемый профиль; чтобы сохранить его системные настройки, создайте собственный профиль на его основе.

| Встроенный профиль | Содержимое | Назначение |
|---|---|---|
| `recommended` | Таблица выше | Системный стартовый набор |
| `cpu-game` | `powersave` governor + EPP `balance_performance` | Кандидат для CPU-sensitive игры; active amd-pstate сам выбирает частоту, `powersave` здесь не означает фиксацию низкой частоты |
| `gpu-game` | `powersave` + EPP `balance_power`, CPU ceiling 2800 MHz | Кандидат на перераспределение общего бюджета APU к GPU; может ухудшить CPU frametime |
| `battery` | `powersave` + EPP `balance_power`, Boost off | Только если целевой FPS/1% low сохраняются; Boost off может сильно замедлить игру |
| `memory-pressure` | Swappiness 150, zram readahead 0, MGLRU on | A/B при подтверждённых memory stalls; не меняет размер/компрессор zram |
| `stock` | Пустой профиль | Возврат сохранённых значений Bosun, не зашитых «заводских» настроек |

Сохранение и переключение:

```bash
# Системный профиль + свои параметры; установить явно, при желании после preview.
bosun profile-save my-game-system --base recommended --set epp=balance_power --set governor=powersave
bosun apply my-game-system --dry-run
bosun apply my-game-system

# Отдельный runtime-профиль для игрового launcher: пустая основа, только нужные параметры.
bosun profile-save my-game --base stock --set governor=powersave --set epp=balance_power --set cpu_max_mhz=2800 --set tdp_w=10
```

В параметрах запуска игры в Steam:

```text
/home/deck/.local/bin/bosun run my-game -- %command%
```

Launcher добавляет настройки игры к текущему глобальному профилю, запускает игру **обычным пользователем** и после выхода восстанавливает предыдущий профиль. Он работает в Desktop и Gaming Mode без запроса sudo при каждом запуске: установленный systemd path unit принимает запрос только на применение/возврат валидированного профиля. Команда игры не передаётся привилегированному помощнику. Помощник выполняется коротко по событию; постоянного процесса и polling-демона нет. Авторизация системного помощника выполняется при установке Bosun через sudo.
В игровой launcher нельзя включать загрузочные изменения, SMT или менять scheduler. Их применяют отдельно. При аварийном завершении launcher через SIGKILL сессия может остаться: её token виден в `bosun status`; выполните `bosun session-end --token TOKEN` или полный откат. Одновременно допускается одна сессия системного power-профиля.

Профили — JSON без исполняемых команд в `~/.config/bosun/profiles`. `--set key=stock` убирает параметр из копии профиля. Список параметров: `bosun catalog`, подробности — [docs/tweaks.md](docs/tweaks.md).

## Дополнительные настройки

Отдельно доступны CPU Boost, SMT, CPU ceiling, EPP/governor, APU TDP **3–15 W в пределах экспортируемых лимитов**, GPU policy `auto/low/high`, swappiness/THP, NVMe/microSD I/O scheduler, `amdgpu.moverate`, `amdgpu.lbpw`, установленный `scx_lavd --autopilot`.

Эти настройки требуют выбора по игре. Например:

```bash
bosun profile-save streaming --base recommended --set sd_scheduler=bfq
bosun profile-save migration-test --base recommended --set moverate=256
bosun profile-save lavd-test --base recommended --set lavd=autopilot
bosun apply lavd-test --dry-run
```

LAVD запускается отдельным принадлежащим Bosun unit только при наличии бинарника `scx_lavd`, sched_ext, BTF и отсутствии другого scheduler manager. Если бинарника нет, параметр пропускается. Автоматической установки scx-пакетов нет; используйте подходящий вашей SteamOS бинарник/пакет [upstream scx](https://github.com/sched-ext/scx). При ошибке attach транзакция откатывается; ядро также имеет механизм возврата к fair scheduler.

GPU frequency policy изменяется реально, но **ручная фиксация MHz не реализована**: на Deck `pp_od_clk_voltage` бывает пустым, поэтому скрытые старые limits нельзя надёжно сохранить для точного отката. Для fixed MHz используйте штатный профиль Steam, а в Bosun в этом случае не задавайте `gpu_mode`/TDP. Undervolt, разгон, повышение аппаратных пределов и отключение термозащит не выполняются.

Другие менеджеры питания (PowerTools, SimpleDeckyTDP, TLP, tuned и т. п.) обнаруживаются. Конкурирующие power-настройки пропускаются; остальные твики работают. Для power-профилей Bosun отключите управляющий сервис или удалите соответствующий Decky-плагин. Статическое наличие plugin.json считается конфликтом, чтобы не гадать, когда плагин начнёт управлять устройством.

## Перезагрузка, сон, обновления SteamOS

Нет постоянно опрашивающего демона. Два systemd unit выполняют короткие проверки при загрузке и после сна, ещё одна пара path/service обслуживает запуск игровых профилей; `active (exited)` у sleep unit не означает работающий процесс.

* Runtime-настройки памяти/overhead, которыми Bosun действительно владеет, повторно проверяются. После сна возвращается только известное исходное значение, и только для управляемых непитающих настроек; неизвестное расхождение сохраняется как конфликт.
* EPP, TDP, Boost, SMT, CPU/GPU power-настройки после сна **не перезаписываются автоматически**. Повторно выберите профиль явно; launcher применяет его при запуске игры. После новой загрузки незавершённая игровая сессия считается истёкшей, выбирается предыдущий глобальный профиль, а владение power-настройками истекает: новый baseline снимается при следующем явном применении.
* При изменении `/etc/os-release`, ядра или версий Mesa/Gamescope автоматическое применение останавливается. Зайдите в Bosun, посмотрите состояние/preview, примените профиль заново. Для runtime-параметров сохраняется baseline новой загрузки/версии, а не старые значения, оставшиеся от предыдущей SteamOS.
* Загрузочный override может сохраниться через SteamOS update; он остаётся активным, пока не отключён. Bosun не утверждает, что уже переданный ядру `mitigations=off` отменяется остановкой runtime replay. Проверяйте `cmdline` и фактические AMDGPU-параметры в статусе; изменение/откат требует reboot.

Bosun не заменяет ядро, Mesa, Gamescope, Proton или пакеты SteamOS. Их замена здесь не обоснована измеренным преимуществом над вашим текущим стеком. [Разбор методов и источники](docs/tweaks.md).

## Откат, конфликты, обновление и удаление

```bash
bosun rollback
# Если менялись boot-параметры — перезагрузиться.

python3 /home/.bosun/app/install.py --update
python3 /home/.bosun/app/install.py --uninstall
```

Обновление также доступно через меню/повторный запуск desktop-установщика. Оно не заменяет ваши профили и исходные значения твиков. Приложение, журнал и recovery-copy сохраняются в `/home/.bosun`; код и журнал защищены владельцем root. Запуск происходит от пользователя с повышением прав только для системных действий.

Перед записью журнал фиксирует исходное и целевое значения; после записи читается фактический результат. Повторное применение идемпотентно. Если запись не удалась, уже выполненные изменения транзакции возвращаются назад. После прерванной операции сначала выполняется recovery (`bosun recover`).

Если параметр после Bosun изменил Steam или другой инструмент, обычный откат **не затирает это изменение** и возвращает код 2. Для scalar-конфликта можно сохранить внешнее значение и снять владение: `bosun release epp`, затем повторить откат/применение. Это явное решение оставить внешнюю настройку, а не «возврат к stock». Для конфликтов прерванной транзакции верните спорный параметр в одно из двух значений из журнала (исходное или записанное Bosun), затем `bosun recover`. Загрузочные/service-файлы автоматически не освобождаются: сначала разрешите изменение файла, затем rollback. До полного разрешения конфликта удаление отказывается убирать программу.

GRUB изменяется через собственный `/etc/default/grub.d/zz-bosun.cfg`; действующий EFI target определяется по установленному `update-grub`. Конфиг генерируется во временный файл и проверяется `grub-script-check` перед атомарной записью. При неподдерживаемой схеме boot-твики пропускаются. Откат удаляет только собственный override и **перегенерирует текущий** GRUB; не подменяет конфигурацию старой копией поверх обновления системы. Recovery-copy перед записью находится в `/home/.bosun/state/grub-before.cfg`. Режим `steamos-readonly` возвращается в прежнее состояние в `finally`; для runtime-твиков выключать его не требуется.

## Проверка пользы

[Пошаговый A/B-протокол и фактически выполненные проверки](docs/testing.md). Есть `bosun capture` для расхода батареи и `bosun analyze` для MangoHud CSV: средний FPS из frametime, 1% low, P95/P99/P99.9 и spikes. Данные тестов остаются у вас, никуда не отправляются.

Сравнивайте LCD и OLED отдельно. Не меняйте разрешение, графику, целевой FPS и сцену между A и B. APU TDP не равен мощности всего устройства: для автономности Bosun считает реальный расход Wh/мощность разряда батареи.

## Разработка

```bash
python3 -m unittest discover -s tests -v
python3 -m py_compile bosun.py install.py bosun/*.py
```

Изолированный CLI принимает `--root DIR` только при наличии marker `.bosun-test-root`; все команды в этом режиме эмулируются, пути не могут выйти наружу. Запускать тесты на живых `/sys` и `/proc` не нужно. GPL-3.0-or-later.
